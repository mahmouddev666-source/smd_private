# تقرير المرحلة الرابعة — تكامل الواجهة (Phase 4)

## 1) ملخص تنفيذي

**الحالة:** مكتملة ومُلتزمة في `8bd594d` ومدفوعة إلى `origin/main`.

تم تنفيذ تكامل الواجهة لمرحلة ONLYOFFICE بالكامل دون تغيير منطق الباك إند المُعتمد في المرحلة الثالثة. تعمل الواجهة الجديدة خلف مفتاحي تشغيل معطّلين افتراضيًا، وتحافظ على مسار المعاينة القديم (Overlay / PDF.js) كما هو عند تعطيل المحرر أو تعذّر تحميله.

## 2) ما تم تنفيذه

### أ) محرّر ONLYOFFICE
- تثبيت الحزمة `@onlyoffice/document-editor-react@2.3.0`.
- إنشاء `src/components/OfficeEditor.tsx`:
  - تحميل SDK ديناميكيًا (`lazy`) فقط عند طلب التحرير.
  - طلب إعداد موقّع من `GET /api/office/config/{file_id}`.
  - حقن أحداث `onAppReady` و`onDocumentStateChange` و`onError` داخل الـ config.
  - معالجة `onLoadComponentError` ومهلة تحميل قابلة للضبط عبر `VITE_OFFICE_LOAD_TIMEOUT_MS`.
  - رسالة خطأ عربية وزر «العودة إلى المعاينة» و«إعادة المحاولة».
  - إغلاق جلسة التحرير بأفضل جهد عبر `POST /api/office/files/{file_id}/sessions/close`.
- إضافة زر واضح «تحرير المستند» في:
  - صف الملف في مكتبة النماذج.
  - رأس نافذة المعاينة.
- يظهر الزر فقط لملفات Word/Excel، ولأدوار `ADMIN`/`HR`، وفي وضع API فقط، وبعد نجاح `GET /api/office/status`.

### ب) إعدادات الورديات والإضافي
- إنشاء `src/components/WorkSettingsManager.tsx` كصفحة جديدة للقائمة الجانبية بعنوان «إعدادات الورديات».
- ربط الصفحة بـ `GET/PATCH /api/settings/work`.
- تحرير: المنطقة الزمنية، مواعيد الورديات الثلاث، بداية الإضافي النهاري وحدّه الليلي، المعاملين، ودقائق السماح للتأخير.
- تحقق محلي مطابق لـ Pydantic، رسائل أسفل كل حقل، عرض رقم الإصدار، ومعالجة تعارض الإصدار `SETTINGS_VERSION_CONFLICT` بإعادة التحميل.
- إخفاء الصفحة عن `VIEWER` في القائمة وفي التوجيه معًا.

### ج) حالة الترخيص في لوحة التحكم
- إضافة بطاقة للقراءة فقط أعلى لوحة التحكم تكتب من `GET /api/license/status`.
- تصنيف الحالات إلى: ساري / يقارب الانتهاء / غير ساري / غير معروف، مع إظهار الأيام المتبقية عند الاقتراب من الانتهاء.
- في وضع العرض المحلي التجريبي تظهر البطاقة صراحةً بعنوان «وضع العرض التجريبي» ولا تُعرض كترخيص حقيقي.
- بيانات الترخيص الحسّاسة (المفتاح، البصمة، المسارات) لا تُعرض في الواجهة.

### د) إخفاء تبويب «المعمارية و SQL»
- أصبح مرئيًا لـ `ADMIN` فقط في `src/components/Navbar.tsx`.
- حماية إضافية في `src/App.tsx` تمنع عرض المحتوى أو الإبقاء على التبويب النشط بعد تغيير الدور.

### هـ) الحفاظ على المسار القديم
- لم يُحذف أو يُعدَّل أي من `Overlay` أو `FormDesigner` أو `SmartForms` أو `formFileParser`.
- عند تعطيل المفتاح، أو فشل فحص الحالة، أو فشل تحميل المحرر، تبقى المعاينة الأصلية والتنزيل والطباعة والتعبئة تعمل كما كانت.
- زر الرجوع من شاشة خطأ المحرر يعيد فتح المعاينة بما فيها القالب المرتبط إن وُجد.

## 4) التشغيل والتفعيل

المفتاحان معطّلان افتراضيًا في `.env.example`:

```env
ONLYOFFICE_ENABLED=false
VITE_ONLYOFFICE_ENABLED=false
VITE_ONLYOFFICE_URL="/onlyoffice"
VITE_OFFICE_LOAD_TIMEOUT_MS=20000
```

لتفعيل التجربة يجب ضبط المتغيرين `ONLYOFFICE_ENABLED` و`VITE_ONLYOFFICE_ENABLED` على `true`، وتشغيل خدمات `onlyoffice` و`api` و`web`، ثم التأكد من نجاح `GET /api/office/status`. لا يكفي مفتاح الواجهة وحده.
